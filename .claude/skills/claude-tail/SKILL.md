# claude-tail

Claude Code の会話を、別ターミナルで `tail -f` のように追いかけて読みやすいテキストにする CLI ツール。
使い方・出力の形は README.md。ここには「どう動くか・なぜそうしたか・ハマった点」を書く。

## ファイル構成

| パス | 中身 |
|---|---|
| `bin/claude-tail.rb` | 本体。1ファイル・標準ライブラリだけ。PATH には拡張子なしのシンボリックリンクで置く |
| `test/claude_tail_test.rb` | minitest。CLI をサブプロセスで叩く。`ruby test/claude_tail_test.rb` |

公開リポジトリ。コード・テスト・このファイルに、実在のセッションの中身・個人のパス・アカウント名を持ち込まない
(テストのデータは架空の短い文字列で作る)。

## 背景: 組み込みコマンドでは足りない理由

| 組み込み | できること | 足りない点 |
|---|---|---|
| `/copy` | 直前の応答をクリップボードへ | 1件ずつで、過去の応答やツールの出力は取れない |
| `/export` | 会話全体をファイル/クリップボードへ | その時点のスナップショットで、流し続けられない |

一方で Claude Code は会話を **1行1イベントの JSONL としてリアルタイムに** ローカルへ書き出している。
これを追いかけて整形すれば、アプリのログのように流し続けられる。

## トランスクリプトの場所と形式

> [!WARNING]
> JSONL の形式は Claude Code の**内部仕様で、公開ドキュメントはない**。以下は実物を観察した結果で、
> 告知なく変わりうる。表示されなくなったら、まず手元のファイルで今の形を確かめる。
>
> ```bash
> f=$(ls -t ~/.claude/projects/*/*.jsonl | head -1)
> jq -r '.type' "$f" | sort | uniq -c
> jq -c 'select(.type=="user" or .type=="assistant") | {type, isMeta, isSidechain, c: .message.content}' "$f" | tail
> ```

### 場所

```
<設定ディレクトリ>/projects/<プロジェクト名>/<セッションID>.jsonl
```

- `<設定ディレクトリ>` は `~/.claude`。環境変数 `CLAUDE_CONFIG_DIR` があればそちら(`config_dir`)。
  ホームのパスを直書きしないのは、公開して他人の環境でも動かすため。テストもこの変数で一時ディレクトリに向ける。
- `<プロジェクト名>` は、Claude Code を起動した作業ディレクトリの絶対パスの **英数字以外をすべて `-` にしたもの**。
  `/` だけでなく `.` も置き換わる(例: `/Users/alice.b/dev/app` → `-Users-alice-b-dev-app`)。
- 作業ディレクトリは**シンボリックリンクを解決した実体のパス**(getcwd)で記録される。`-C` にリンクを含むパスを
  渡されると名前がずれるので、`project_dir` は `expand_path` と `realpath` の両方を候補にして、存在する方を使う。
  macOS の一時ディレクトリ(`/var` → `/private/var`)でテストが全部落ちて気づいた。
- `<セッションID>` は UUID。1セッション = 1ファイル。発言のたびに追記される。

### 1行の形(必要なところだけ)

`type` で種類が分かれる。会話の本文に関係するのは `user` と `assistant` だけで、それ以外
(`ai-title` `attachment` `permission-mode` `file-history-snapshot` `mode` `last-prompt` など)はメタ情報。

| `type` | `message.content` | 中身 |
|---|---|---|
| `user` | 文字列 | 人が入力したプロンプト |
| `user` | 配列(`tool_result`) | ツールの実行結果。人の発言ではないが `user` として記録される |
| `user` | 配列(`text`)+ `isMeta: true` | スキル本文などの注入。人の発言ではない |
| `assistant` | 配列(`text` / `thinking` / `tool_use`) | 応答。**1回の応答が要素ごとに別の行に分かれて**記録される |

| フィールド | 用途 |
|---|---|
| `timestamp` | ISO 8601(UTC)。表示時にローカル時刻へ |
| `isSidechain` | `true` ならサブエージェントの会話。メインの会話と分ける |
| `aiTitle`(`type: "ai-title"` の行) | セッションのタイトル。何度か更新されるので最後の行を使う |

`tool_use` の `input` はツールごとに形が違う(Bash なら `command` が文字列)。
`tool_result` の `content` は文字列のことも、`{type: "text", text: ...}` の配列のこともある(画像などは `[image]` と出す)。
エラーのときは `is_error: true` が付く(`◀ result (error)` と出す)。

## 実装の要点

### セッションの選び方(`resolve`)

- 引数が `.jsonl` で終わる/既存のファイル: そのファイルを直接使う(プロジェクトのディレクトリは無くてよい)。
- 引数がそれ以外: セッションID の前方一致。0件・2件以上はエラー(黙って1件目を選ばない)。
- 引数なし: 更新日時がいちばん新しいもの。
- **「最新」は同じディレクトリでセッションを並行して開いていると外れる。** 選んだ ID とタイトルを stderr に出し、
  2番目に新しいセッションも10分以内(`CONCURRENT_WINDOW`)に更新されていれば警告する。
- タイトルの取得は全行をパースすると重いので、`"ai-title"` を含む行だけパースする。

### 追いかけ(`tail`)

ファイルを `rb` で開き、`read_nonblock` で読めるだけ読み、末尾に来たら0.5秒待ってまた読む。

- **書きかけの行を JSON としてパースしない。** 読んだ時点で末尾の行が途中までしか書かれていないことがある。
  バイト列のままバッファに溜め、**改行まで揃った行だけ**取り出して処理する。`gets` は末尾の改行なしの断片も
  1行として返すので使わない。
- バッファをバイナリ(`''.b`)にしているのは、マルチバイト文字がチャンクの境目で割れても `index("\n")` が
  文字境界で困らないため。行を切り出してから UTF-8 として扱い、`scrub` してからパースする。
- パースに失敗した行は捨てる(落とさない)。
- `-n` は末尾へ seek する。**末尾が改行で終わっていなければ書きかけの行の途中**なので、
  次の改行までの断片を捨てる(`skip_partial`)。そうしないと続きの断片を壊れた JSON として掴む。
- 標準出力と `-o` のファイルには1件ごとに `flush` する(パイプや `tee` で溜まらないように)。
- `INT` / `TERM` はトラップして終了コード 0。`head` に渡して読み手が先に閉じた `EPIPE` も 0。それ以外のエラーは 2。

### 整形(`format`)

順序:

1. `type` が `user` / `assistant` 以外 → 捨てる
2. `isMeta` か `isSidechain` が真 → 捨てる
3. `content` が文字列 → 見出し + 本文
4. `content` が配列 → 要素ごとに `text` / `tool_use` / `tool_result` を文字列にして結合(`thinking` は捨てる。
   ツールは `-t` の時だけ)。`tool_result` だけの user の行は見出しを `tool` にする(人の発言と紛れないように)
5. 結合結果が空 → 捨てる(`thinking` だけの行や、`-t` なしのツール行)

- 見出しは `━━━ user 2026-01-01 09:00:00 ━━━`。Markdown の `##` にしないのは、応答の本文自体に `##` 見出しが
  入っていて区別がつかなくなるため。
- ツールの入出力はコードフェンスで囲む。**出力に ``` が入っていると閉じてしまう**ので、中のいちばん長い
  バッククォートの並びより1つ長いフェンスにする(`fence`)。
- Bash は `command` をそのまま、他のツールは `input` を `JSON.pretty_generate`。

### 環境に依存しないための決めごと

- **Ruby は 4.0.5 以上を推奨し、それ未満は保証しない。** 古い Ruby(macOS 標準の 2.6 など)への互換対応はしない
  (一度 2.6 互換にしかけたが、不要と判断した)。外部の gem には依存しない。
- **ロケールに依存しない。** cron / launchd 相当の `LANG` なしでは既定エンコーディングが US-ASCII になって
  日本語で落ちるので、冒頭で UTF-8 に固定している(テスト `test_without_locale`)。
- 時刻は `Time#localtime` で表示側のタイムゾーンに合わせる。テストは `TZ=UTC` で固定。

## 動作確認

```bash
ruby test/claude_tail_test.rb                       # 一通り(追従・書きかけ行・-n・Ctrl-C・ロケールなし を含む)
claude-tail -l
claude-tail <ID> --no-follow -t | head -40          # 実際のセッションで目視
```

## 既知の制約・改善の余地

- JSONL の形式は内部仕様。表示されなくなったら、冒頭の `jq` で今の形を確かめて `format` を直す。
- プロジェクト名の変換規則(英数字以外を `-`)も観察結果。変わったら `project_dir` を直す。
- 追従はポーリング(0.5秒)。即時性が要るなら OS のファイル監視(kqueue / inotify)に置き換えられる。
- セッションを途中で切り替えても追従先は変わらない(起動時に選んだファイルを追い続ける)。
- 1回の応答が複数行に分かれると、同じ応答に `assistant` の見出しが複数出る(`thinking` だけの行は捨てるので
  出ないが、`text` と `tool_use` が分かれると `-t` 時に見出しが続く)。まとめたければ直前の見出しと種類が同じなら
  見出しを省く、などの処理を足す。
